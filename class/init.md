# C++ 기초 - init.cpp : 개발 환경 준비와 한글 깨짐 방지

이 문서는 **example/src/init.cpp**를 바탕으로, 수업을 시작하기 전에 확인해야 할 **개발 환경 설정**과 **한글이 깨져 보이는 문제**의 원인·해결 방법을 정리한 내용입니다.

## 1. 이 수업의 프로젝트 구조

```
class_cpp/
├─ class/                    <- 강의 문서 (지금 보고 있는 이 폴더)
│   ├─ init.md
│   └─ class1.md ~ class16.md
└─ example/
    ├─ example.slnx          <- 이 파일을 Visual Studio 로 연다
    ├─ example/              <- 프로젝트 설정 파일
    └─ src/
        ├─ init.cpp
        ├─ ex1.cpp ~ ex16.cpp    <- 강의별 예제 코드

            ├─ point/

- **class/classN.md** 를 읽으면서 **example/src/exN.cpp** 를 실행하는 방식으로 진행합니다.

  단계별로 확인하고 싶으면 위쪽 코드를 주석 처리하고 아래 단계의 주석을 풀어 실행하면 됩니다.

## 2. 실행할 파일 하나만 빌드에 포함하기

`ex1.cpp` ~ `ex16.cpp` 는 **각각 `main()` 함수를 하나씩 가지고 있습니다.**
C++ 프로그램에는 `main()` 이 하나만 있어야 하므로, **한 번에 하나의 파일만** 빌드에 포함해야 합니다.

처음 프로젝트를 열면 **ex1.cpp 만 빌드에 포함**되어 있고 나머지는 모두 제외되어 있습니다.

### 다른 예제를 실행하는 방법

1. **솔루션 탐색기**에서 지금 실행 중인 파일(예: `ex1.cpp`)을 오른쪽 클릭
2. **속성** → **일반** → **빌드에서 제외** → **예** 로 변경 → 확인
3. 실행하고 싶은 파일(예: `ex2.cpp`)을 오른쪽 클릭
4. **속성** → **일반** → **빌드에서 제외** → **아니오** 로 변경 → 확인
5. **Ctrl + F5** (디버깅하지 않고 시작)

> **오류 메시지로 확인하기**
> `LNK2005: main이(가) 이미 정의되어 있습니다` 라는 링크 오류가 나면 **두 개 이상의 파일이 빌드에 포함**된 것입니다.
> `LNK1561: 진입점을 정의해야 합니다` 라는 오류가 나면 **아무 파일도 포함되지 않은 것**입니다.

## 3. 문제 상황 : 한글이 깨지는 경우

Windows 환경에서 Visual Studio 로 C++ 프로그램을 실행하면, 한글을 `cout` 으로 출력할 때 다음과 같이 깨져 보이는 경우가 있습니다.

```
?????~!
```

또는 아무것도 출력되지 않거나, 이상한 문자가 출력됩니다.

## 4. 원인 : 인코딩이 3단계로 이어진다

`cout << "안녕"` 이 화면에 나오기까지 **한글이 세 번 손을 거칩니다.**

```
[1] 소스 파일          [2] 실행 파일(.exe)            [3] 콘솔
어떤 인코딩으로     →  컴파일러가 어떤 인코딩으로  →  어떤 인코딩으로
저장했나?              바꿔 넣었나?                   읽나?
```

**이 세 개가 맞아떨어져야 정상 출력됩니다.** 하나라도 어긋나면 깨집니다.

| 단계 | 무엇이 정하나 | 기본값 (한국어 Windows) |
|------|---------------|--------------------------|
| **[1] 소스 인코딩** | 저장할 때 에디터가 정함. **BOM 이 있으면 확실해진다** | BOM 없으면 CP949 로 가정 |
| **[2] 실행 문자셋** | 컴파일러 옵션 `/utf-8` 유무 | **CP949** (`/utf-8` 없을 때) |
| **[3] 콘솔 코드 페이지** | `chcp` 명령으로 확인 | 보통 **949**, 요즘은 65001 인 경우도 있음 |

> **`locale` 은 이 3단계에 끼어들지 않습니다.**
> `setlocale` 이 필요한 경우는 따로 있습니다. **7장**에서 설명합니다.

## 5. BOM 이란?

### 5.1 파일 맨 앞의 보이지 않는 3바이트

**BOM = Byte Order Mark (바이트 순서 표시)** 는 파일 맨 앞에 붙는 표식으로, 내용이 아니라 **"이 파일은 이 인코딩입니다"라는 꼬리표** 입니다.

`ex1.cpp` 의 실제 맨 앞 바이트입니다.

```
EF BB BF 2F 2F 3D 3D 3D 3D 3D ...
└──┬───┘ └──────────┬────────┘
  BOM         // =====   ← 여기부터 진짜 내용
```

| 인코딩 | BOM 바이트 |
|--------|-----------|
| **UTF-8** | `EF BB BF` |
| UTF-16 LE | `FF FE` |
| UTF-16 BE | `FE FF` |
| BOM 없음 | (없음) |

에디터는 BOM 을 화면에 보여주지 않습니다. 그래서 **눈에는 똑같은데 파일 크기만 3바이트 큰** 상태가 됩니다.

---

### 5.2 BOM 이 있고 없고의 차이 (실측)

같은 소스를 저장 인코딩만 바꿔서 컴파일한 결과입니다.

```cpp
#include <iostream>
using namespace std;
int main() { cout << "안녕" << endl; }
```

| 저장 방식 | 파일 크기 | 컴파일 | 실행 결과 |
|-----------|-----------|--------|-----------|
| **UTF-8 + BOM** | 88 B | 경고 없음 | `안녕` |
| UTF-8 (BOM 없음) | 85 B | **경고 C4819** | `?덈뀞` |
| CP949 (ANSI) | 83 B | 경고 없음 | `안녕` |
| UTF-16 LE | 164 B | 경고 없음 | `안녕` |

**BOM 없는 UTF-8 만 깨집니다.** 컴파일러가 이렇게 판단하기 때문입니다.

```
BOM 있음  →  "UTF-8 이구나"      →  올바르게 읽음
BOM 없음  →  "그럼 CP949 겠지"    →  UTF-8 바이트를 CP949 로 오해  →  깨짐
```

> ### warning C4819 는 한글 깨짐의 신호탄입니다
> ```
> warning C4819: 현재 코드 페이지(949)에서 표시할 수 없는 문자가 파일에 들어 있습니다.
> ```
> 이 경고가 보이면 **BOM 없는 UTF-8 파일**입니다. 아래 5.3 대로 다시 저장하세요.

---

### 5.3 BOM 은 저장할 때 붙는다

| 도구 | 방법 |
|------|------|
| **Visual Studio** | `파일` → `다른 이름으로 저장` → 저장 버튼 옆 **▼** → `인코딩하여 저장` → **"유니코드(UTF-8, 서명 있음) - 코드 페이지 65001"** |
| **VS Code** | 오른쪽 아래 `UTF-8` 클릭 → `인코딩하여 저장` → **`UTF-8 with BOM`** |
| 메모장 | `다른 이름으로 저장` → 인코딩 **`UTF-8(BOM)`** |

> Visual Studio 의 **"서명 있음(with signature)"** 이 바로 BOM 입니다.

**이 수업의 모든 `.cpp` / `.h` 는 UTF-8 + BOM 으로 저장되어 있습니다.**
그래서 프로젝트 설정을 건드리지 않아도 한글이 그대로 나옵니다.

## 6. 그래도 깨진다면 — 경우별 해결

먼저 **어느 단계가 어긋났는지** 확인하세요.

```
콘솔에서 chcp 를 실행해 현재 코드 페이지를 확인합니다.
    Active code page: 949    ← 기본
    Active code page: 65001  ← UTF-8
```

### 경우 A : 콘솔이 949 (대부분)

**아무것도 하지 않아도 됩니다.** 소스만 UTF-8+BOM 이면 정상 출력됩니다.

```
소스 UTF-8+BOM  →  exe 안에는 CP949  →  콘솔 949  ✅
```

### 경우 B : 콘솔이 65001 인데 깨진다

exe 는 CP949 인데 콘솔이 UTF-8 로 읽어서 생기는 문제입니다. **둘 중 하나**를 하세요.

**(1) 콘솔을 949 로 되돌린다**
```
chcp 949
```

**(2) exe 도 UTF-8 로 만든다** — 프로젝트 속성에 `/utf-8` 추가
```
프로젝트 속성 → C/C++ → 명령줄 → 추가 옵션 :  /utf-8
```

> `/utf-8` 은 **소스와 실행 파일을 모두 UTF-8 로** 통일합니다.
> 이러면 BOM 없이도 안전하지만, **콘솔도 반드시 65001** 이어야 합니다.

### 경우 C : 프로그램 안에서 콘솔을 바꾸고 싶다

```cpp
#include <iostream>
#include <windows.h>
using namespace std;

int main()
{
	SetConsoleOutputCP(65001);   // 65001 = UTF-8

	cout << "안녕하세요~!" << endl;
}
```

- **`/utf-8` 로 빌드했을 때만** 짝이 맞습니다.
- Windows 전용이며, 콘솔 글꼴이 한글을 지원해야 합니다.

## 7. `setlocale` 은 언제 필요한가

### 7.1 `cout` 에는 필요 없습니다

```cpp
cout << "안녕" << endl;   // setlocale 없이도 잘 나온다
```

`"안녕"` 같은 **좁은 문자열 리터럴**은 **컴파일 시점에 이미 바이트로 확정**됩니다. `cout` 은 그 바이트를 콘솔로 그대로 흘려보낼 뿐이라, 프로그램의 locale 설정과 아무 상관이 없습니다.

### 7.2 `wcout` 에는 반드시 필요합니다

```cpp
#include <iostream>
#include <locale.h>
using namespace std;

int main()
{
	setlocale(LC_ALL, "");           // wcout 을 쓰기 "전에" 부른다

	wcout << L"안녕하세요~!" << endl;   // 정상 출력
}
```

`wchar_t`(와이드 문자)를 콘솔로 내보낼 때는 **유니코드 → 콘솔 인코딩 변환**이 필요하고, 그 변환 규칙을 정하는 것이 locale 입니다.

---

### 7.3 순서를 틀리면 되돌릴 수 없습니다 (실측)

`init.cpp` 의 **[실험 1]** 을 실행해 보세요.

```cpp
int main()
{
	cout  << "1. cout  : 안녕하세요~!" << endl;
	wcout << L"2. wcout : 안녕하세요~!" << endl;

	setlocale(LC_ALL, "");
	wcout << L"3. wcout : 안녕하세요~!" << endl;

	wcout.clear();
	wcout << L"4. wcout : 안녕하세요~!" << endl;
}
```

**실제 출력 — 4줄이 아니라 2줄입니다**
```
1. cout  : 안녕하세요~!
2. wcout : 4. wcout : 안녕하세요~!
```

| 줄 | 결과 | 이유 |
|----|------|------|
| 1 | 정상 | `cout` 은 locale 과 무관 |
| 2 | **`"2. wcout : "` 까지만** | 아스키는 나가지만 `안` 에서 변환 실패 → **failbit 켜짐**, `endl` 도 실행 안 됨 |
| 3 | **아무것도 안 나옴** | locale 을 고쳤어도 **failbit 가 남아 있어** 통째로 무시 |
| 4 | 정상 | `wcout.clear()` 로 실패 표시를 지운 뒤라야 되살아남 |

> ### 스트림은 한 번 실패하면 스스로 회복하지 않습니다
> `cout` / `wcout` 은 실패 상태(`failbit`)가 되면 **그 뒤의 모든 출력을 조용히 버립니다.**
> 에러 메시지도 나오지 않아서 원인을 찾기 어렵습니다.
>
> **`setlocale(LC_ALL, "");` 은 `main` 의 첫 줄에 두세요.** 이것이 이 문제를 피하는 유일하게 확실한 방법입니다.

### 7.3 `setlocale` 이 영향을 주는 것

| 대상 | 영향 |
|------|------|
| `wcout` / `wprintf` 의 한글 출력 | **필요** |
| `cout << "한글"` | 무관 |
| 숫자의 소수점·자릿수 구분 (`1,234.56` vs `1.234,56`) | 영향 있음 |
| 날짜·시간 형식 | 영향 있음 |
| `isalpha`, `toupper` 등의 문자 분류 | 영향 있음 |

```cpp
char* setlocale(int category, const char* locale);
```

| 매개변수 | 설명 |
|----------|------|
| `LC_ALL` | 모든 범주 |
| `LC_CTYPE` | 문자 분류 및 변환 |
| `LC_NUMERIC` | 숫자 형식 (소수점 등) |
| `LC_TIME` | 날짜/시간 형식 |
| `""` | 시스템 기본 locale 사용 |
| `"C"` | 기본(영문) locale 로 초기화 (기본값) |
| `"Korean"` | 한국어 locale 명시적 지정 (Windows) |

> `example/src/init.cpp` 에 `setlocale` 이 들어 있는 것은 **관습적인 안전장치**입니다.
> 없어도 `cout` 은 잘 동작하지만, 나중에 `wcout` 을 쓰게 될 때를 대비한 것입니다.

## 8. 정리 표

| 증상 | 원인 | 해결 |
|------|------|------|
| 소스의 한글 주석이 에디터에서 깨짐 | 저장 인코딩과 에디터 해석이 다름 | **UTF-8(BOM 포함)** 으로 다시 저장 |
| `warning C4819` | **BOM 없는 UTF-8** 파일 | BOM 포함으로 저장 **또는** `/utf-8` 추가 |
| 콘솔 949 인데 깨짐 | 소스가 BOM 없는 UTF-8 | BOM 포함으로 저장 |
| 콘솔 65001 인데 깨짐 | exe 는 CP949, 콘솔은 UTF-8 | `chcp 949` **또는** `/utf-8` 추가 |
| `wcout << L"한글"` 이 안 나옴 | locale 미설정 | `setlocale(LC_ALL, "");` |
| 그래도 안 되면 | — | 주석·문자열을 **영문으로만** 작성 |

**가장 중요한 한 줄**

> 소스는 **UTF-8 + BOM**, 콘솔은 **949**. 이 조합이 Visual Studio 의 기본이자 가장 안전합니다.

## 9. 이 프로젝트의 컴파일 설정

| 항목 | 값 | 이유 |
|------|-----|------|
| **C++ 언어 표준** | `stdcpp20` (C++20) | `auto`, 람다, 범위 기반 for, 스마트 포인터 등을 모두 사용하기 위해 |
| **문자 집합** | 유니코드 | Windows API 용 `UNICODE` 매크로 정의. **문자열 리터럴 인코딩과는 무관** |
| **전처리기 정의** | `_CRT_SECURE_NO_WARNINGS` | `strcpy_s` 대신 `strlen`, `strcmp` 등을 쓸 때 나오는 경고를 끄기 위해 |
| **경고 수준** | Level3 | 실수를 잡아 주되 지나치게 많지 않은 수준 |
| **소스 인코딩** | UTF-8 (BOM 포함) | `/utf-8` 옵션 없이도 한글이 깨지지 않게 |
| `/utf-8` 옵션 | **사용하지 않음** | 콘솔이 949 인 기본 환경에 맞추기 위해 |

> **"문자 집합 : 유니코드"** 는 `MessageBoxW` 처럼 Windows API 의 와이드 버전을 쓰게 하는 설정일 뿐입니다.
> `cout << "한글"` 의 인코딩은 **BOM 과 `/utf-8` 옵션**이 결정합니다. (5장 참고)

## 10. 템플릿으로 활용하기

새 프로그램을 작성할 때 아래 코드를 **시작 템플릿**으로 사용하세요.

```cpp
#include <iostream>
using namespace std;

int main()
{
	// 여기서부터 코드 작성
	cout << "안녕하세요~!" << endl;

	return 0;
}
```

**파일을 저장할 때 반드시 `UTF-8(서명 있음)` 을 선택하세요.** 그것만으로 한글 문제는 끝납니다.

`wchar_t` 를 쓸 계획이라면 `setlocale` 을 추가합니다.

```cpp
#include <iostream>
#include <locale.h>
using namespace std;

int main()
{
	setlocale(LC_ALL, "");           // wcout 을 쓸 때만 필요 (7장 참고)

	cout  << "안녕하세요~!" << endl;
	wcout << L"안녕하세요~!" << endl;

	return 0;
}
```

---

한글 깨짐의 원인은 **locale 이 아니라 인코딩 3단계의 불일치**입니다. 소스를 **UTF-8(BOM 포함)** 으로 저장하는 습관 하나면 대부분 해결됩니다.

다음 강의부터는 **[class1.md](class1.md)** 를 보면서 `example/src/ex1.cpp` 를 실행해 보세요.
